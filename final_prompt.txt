### Project Overview
This is a Flask REST API application for calculating coupon discounts on e-commerce orders. The original project contains **6 critical bugs** that must be identified and fixed:

#### Bug #1: ZeroDivisionError on discount_rate = 0
- **Location**: `src/app.py` line 32 (calculation endpoint)
- **Current Behavior**: When `discount_rate` is 0, the code executes `original_price / discount_rate`, causing a ZeroDivisionError that returns HTTP 500
- **Root Cause**: Direct division without zero-check validation
- **Expected Behavior**: Should return HTTP 400 with clear error message: `"discount_rate cannot be zero"`

#### Bug #2: Missing Input Parameter Validation
- **Problem**: No validation that required parameters (`original_price`, `discount_rate`) exist in the request
- **Current Behavior**: Missing parameters cause `TypeError` or `AttributeError` exceptions (HTTP 500)
- **Expected Behavior**: Should return HTTP 400 with specific message indicating which parameter is missing

#### Bug #3: Missing Parameter Type Validation
- **Problem**: Does not validate that parameters are numeric (int or float)
- **Current Behavior**: String inputs like `"100"` and `"0.8"` may cause unexpected behavior or silently fail
- **Expected Behavior**: Should return HTTP 400 with message: `"<parameter> must be numeric (int or float)"`

#### Bug #4: Missing Parameter Range Validation
- **Problem**: Does not validate that `discount_rate` is within valid business range (0 < discount_rate <= 1)
- **Current Behavior**: Accepts negative values, zero, or values > 1, producing nonsensical results
- **Expected Behavior**: Should return HTTP 400 with message: `"discount_rate must be between 0 (exclusive) and 1 (inclusive)"`

#### Bug #5: Incorrect Business Logic (Critical)
- **Problem**: Uses division formula instead of multiplication for discount calculation
- **Current Code**: `final_price = original_price / discount_rate`
- **Example Failure**: When `original_price=100` and `discount_rate=0.8`, returns `125` instead of `80`
- **Expected Logic**: `final_price = original_price * discount_rate`
- **Correct Example**: When `original_price=100` and `discount_rate=0.8`, should return `80.0`

#### Bug #6: Missing Comprehensive Error Handling
- **Problem**: No try-except blocks to catch exceptions and return proper error responses
- **Current Behavior**: Unhandled exceptions return generic HTTP 500 errors
- **Expected Behavior**: All errors should return HTTP 400 (client errors) with descriptive JSON messages

### Original Buggy Code Reference

**`src/app.py` (buggy version)**:
```python
from flask import Flask, request, jsonify

app = Flask(__name__)

@app.route('/api/coupons/calculate', methods=['POST'])
def calculate():
    data = request.json
    
    # Get parameters directly without any validation
    original_price = data.get('original_price')
    discount_rate = data.get('discount_rate')
    
    # ⚠️ Bug: Direct division operation without checking if divisor is zero
    final_price = original_price / discount_rate
    
    saved_amount = original_price - final_price
    
    return jsonify({
        'original_price': original_price,
        'discount_rate': discount_rate,
        'final_price': final_price,
        'saved_amount': saved_amount
    })

@app.route('/health', methods=['GET'])
def health():
    return jsonify({'status': 'ok'})

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=5000)
```
